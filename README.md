## 先分清需求：你要的是“存文件”还是“跑服务”

需求不同，方案差得很远。私有云这个词被用得太宽，至少可以拆成三类。

**文件备份与共享**。手机照片自动同步、电脑资料备份、几个人之间互传大文件。这类需求吃的是硬盘容量，对 CPU 要求很低，一台低功耗小主机甚至旧笔记本就能胜任。

**应用与代码托管**。自建 Git 服务、跑几个 Docker 容器、部署内部 API 或测试环境。这类需求吃内存和网络，还需要一个稳定的公网入口，否则外面访问不了。

**企业虚拟化**。多台虚拟机、OpenStack 或 Proxmox VE 这类平台、集中存储。这是另一个量级的工程，涉及计算、存储、网络虚拟化和专人运维，不适合用一台迷你主机凑合。

大部分搜「私有云服务器搭建」的人落在前两类。下面的内容也主要围绕这两类展开。

## 物理机自建：硬件清单和算得出来的成本

一台能用的个人私有云服务器，硬件门槛比想象中低。以常见的低功耗方案为例：华擎 J3455-ITX 这类板载四核处理器的主板，加两条内存和一个小机箱，整机成本千元左右；5 口千兆交换机加一台千兆路由器约 200 元；硬盘才是大头，3 块 2TB 机械盘约 1100 元，再加一块 200 多元的固态做系统盘，合计约 1400 元。整套下来 2600 元上下。

这个配置放到今天参考意义有限，DDR3 内存已经过时，二手市场价格也变了。但成本结构没变：**主机占小头，硬盘占大头**。

硬盘是自建方案里最不该省钱的地方，几条经验值得记：

- 别买二手机械硬盘，翻新盘同理。除非你对数据可靠性要求不高，或者有别的备份手段。
- 别用移动硬盘长期联机。移动硬盘是为低频离线访问设计的，连续几天高负荷读写就可能出问题。解压大量小文件这种操作尤其伤盘——有案例是在移动硬盘上解压一个 150GB、包含几百万个小文件的压缩包，硬盘直接损坏。
- 系统盘别选 120GB 这种容量。同样 300 次擦写寿命，120GB 只能写入约 35TB，240GB 能写到约 70TB，寿命差一倍。

机械硬盘的寿命可以粗算。普通消费级硬盘按一周 8×5 小时使用、MTBF 80 万小时、质保三年推，大概率能用 3 万小时左右，也就是 3 到 4 年；企业级硬盘 7×24 运行、MTBF 100 到 120 万小时、质保 5 年，推算下来 5 到 6 年。超过这个时间，故障就不再是小概率事件，所以重要数据必须留备份。

还有几项常年支出容易被忽略：电费、网络，以及你自己的时间。机器不能放在会停电的地方，宿舍欠费断电、半夜熄灯都是常见情况。

## 公网访问：自建方案绕不过去的一道坎

私有云搭好只是第一步，能不能在外面访问才是分水岭。

大部分家庭宽带和校园网不提供公网固定 IP，运营商给的是 NAT 后的地址。想从公网访问，就得做内网穿透：自己买一台有公网 IP 的云服务器，两边跑 frp 之类的工具，再用 Nginx 把 80/443 反代到穿透端口。这样一台公网服务器可以同时穿透多个服务、绑定多个域名，比只开一个端口灵活。

这套方案能跑通，但带宽是硬伤。内网千兆环境下，向自建 NAS 读写数据能跑到 100MB/s 左右；换到公网，5Mbps 带宽的服务器下载速度只有 500 到 600KB/s。换算一下，5Mbps ÷ 8 ≈ 625KB/s，传一个 4GB 的文件按 600KB/s 算要接近两个小时。同步照片、备份手机视频这类操作，体验会很差。

两个容易忽略的点：

1. 内网穿透用的那台云服务器本身要花钱。配置不用高，但带宽单价不便宜，而带宽恰恰是决定体验的那一项。
2. 用国内节点加域名对外提供网站服务，通常需要完成 ICP 备案。

换句话说，自建方案并没有真正绕开云服务器，只是把云服务器降级成了“管道”，还得额外维护一套穿透配置。

## 系统和软件：装什么，怎么装

操作系统没那么纠结。Ubuntu Server 是比较稳的平衡点：软件源新、社区资料多、遇到问题搜得到答案。CentOS 适合对稳定性要求高、不追新的场景，但要留意版本策略的变化。想尝鲜可以选 Fedora Server，代价是部分软件还没适配最新版本，比如偶尔会遇到 Docker 装不上的情况。

软件栈按需求组合：

- **文件同步与在线文档**：Nextcloud。Web 界面操作，能分享文件、多人协作编辑文档，行为接近网盘。Seafile 和 ownCloud 是同类替代。
- **局域网挂载**：Samba。把服务器硬盘映射成网络驱动器，适合内网高速读写。
- **代码托管**：Gogs，轻量的自建 Git 服务。
- **Web 服务与反向代理**：Nginx，配合 PHP 和 MariaDB 跑 Nextcloud。

部署顺序大致是：装系统 → 配置 SSH → 装 Nginx 和数据库 → 部署 Nextcloud → 配防火墙。

SSH 这一步值得多花两分钟：改掉默认的 22 端口，禁止 root 直接登录，用普通用户加 sudo。配置文件在 `/etc/ssh/sshd_config`，改完 reload 一下 sshd 服务。

云服务器上还有一步：防火墙或安全组默认不会放行所有端口，Nextcloud 要用的 80/443 或者你自定义的端口，需要在控制台里手动放行。

## 安全与备份：搭完之后最容易忽略的两件事

第一件是防火墙。不少人配置完发现服务访问不了，原因就是端口没放行。规则很简单：需要对外提供服务的端口设为允许，其余全部拒绝。SELinux 如果搞不定可以先关，但防火墙规则不能省。

第二件是备份。物理机方案里，主板不支持 RAID 的话（不少 ITX 主板都不支持），就只能靠定期拷贝到另一块硬盘。云服务器在这件事上省事得多：控制台点几下就能创建快照，系统盘和数据盘都能回滚。

还有个细节：断电或意外重启后，服务要能自己起来。写几个开机自启的脚本，把容器、Nginx、数据库都设成自动启动，能省掉很多麻烦。

## 常见问题

**私有云服务器搭建要花多少钱？**

物理机自建一次性投入 2000 到 3000 元（主机、硬盘、网络设备），之后是电费和硬盘更换；云服务器按月或按年付费，价格由配置和带宽决定，没有硬件折旧。

**没有公网 IP 能搭私有云吗？**

能，但要额外做内网穿透，需要一台有公网 IP 的服务器做中转。云服务器方案本身自带公网 IP，不存在这个问题。

**旧笔记本能当私有云服务器吗？**

可以。闲置笔记本、迷你主机都能装 Linux 跑 Nextcloud，性能对个人使用足够。要注意的是长期通电下的散热和电池老化。

**云服务器上的私有云，数据还算私有吗？**

数据存在云厂商的物理机上，逻辑上由你的账号、密钥和安全组控制。对数据物理位置有硬性要求的场景，物理机自建更合适；普通个人和小团队使用，云服务器的隔离能力和快照机制通常够用。
